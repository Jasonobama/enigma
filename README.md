# 恩尼格玛密码机模拟器 (Enigma Machine Simulator)

模拟二战德军 **恩尼格玛密码机（Enigma I / M3）** 的完整加解密过程，提供图形界面操作。

![Python](https://img.shields.io/badge/Python-3.8+-blue)
![License](https://img.shields.io/badge/License-MIT-green)

---

## 功能特性

- **3 转子系统** — 支持 I、II、III、IV、V 五种历史转子型号，可自由组合
- **插线板 (Steckerbrett)** — 最多 13 对字母交换，支持可视化连线
- **双反射器** — B 型和 C 型反射器可选
- **双步进机制** — 完整模拟真实恩尼格玛机的转子步进逻辑
- **环设置 (Ringstellung)** — 每个转子独立配置环偏移
- **预设配置** — 一键加载多组历史/演示配置
- **暗色主题 GUI** — 基于 tkinter/ttk 的现代暗色界面，三标签页布局

## 界面说明

程序启动后显示三个标签页：

### 1. 加密 / 解密

| 区域 | 说明 |
|------|------|
| **输入文本** | 在此输入待加密或待解密的文本。支持 A-Z 字母（自动转大写），非字母字符原样保留 |
| **🔒 加密** | 对输入文本执行加密，转子会随每个字母转动，结果输出到下方 |
| **🔓 解密** | 先将机器重置到初始位置，再对输入文本执行解密 |
| **🗑 清空输入** | 清空输入框和输出框 |
| **📋 复制输出** | 将输出结果复制到系统剪贴板 |
| **输出结果** | 以绿色字体显示加密/解密结果 |

> **注意**：恩尼格玛机的加解密是对称的——用相同初始配置加密得到密文，用相同配置再加密一次密文即还原明文。

---

### 2. 机器配置

#### 预设配置
顶部下拉列表提供 4 组预设配置，选中后点击「加载并应用」即可一键应用：
- **默认** — I-II-III, B型反射器, A-A-A 环设置, 初始 AB/CD/EF 插线
- **历史上的实例** — I-II-III, G-X-Q 环设置, K-T-K 初始位置
- **海军型** — III-I-II, Z-Z-Z 环设置（展示不同转子顺序）
- **C型反射器** — IV-V-III, C型反射器

#### 转子配置表
以表格形式紧凑展示三个转子的全部参数：

| 列 | 说明 |
|------|------|
| **转子位置** | 表格按右转子(快速) / 中转子 / 左转子(慢速)排列，字母行进方向为 **右→左** |
| **类型** | 选择 I~V 型转子（三个转子不能重复） |
| **环设置** | 环偏移量，A=0, B=1, …, Z=25 |
| **初始位置** | 加密前转子的起始字母位置 |
| **缺口** | 自动显示当前所选转子型号的缺口字母 |

#### 反射器类型
选择 B 型（标准）或 C 型反射器。

#### 插线板 (Steckerbrett)
- **可视化画布**：顶部显示 A-Z 字母排列，有连接的字母以绿色高亮，连线用红色曲线表示
- **添加连接**：从 **左侧下拉框** 选第一个字母，**右侧下拉框** 选第二个字母，点击「➕ 添加」
- **智能过滤**：下拉框 **只显示尚未被占用的字母**，避免冲突
- **清除全部**：移除所有插线板连接
- 当前连接列表以文字形式显示在下方

> 插线板最多支持 13 对字母交换（即 26 个字母全部配对）。每添加一对连接后，两个下拉框的选项会即时更新。

#### 应用配置
完成所有设置后，点击「**✔ 应用配置**」按钮使配置生效。配置会验证转子不重复，并重建密码机实例。

### 3. 转子状态

以可视化方式展示当前转子组状态：

- **转子窗口**：每个转子以矩形表示，中央深色窗口显示当前字母位置（绿色大字），窗口上下各显示相邻字母
- **环设置 & 缺口**：在转子下方标注环设置字母和缺口位置
- **反射器**：紫色矩形，标注反射器类型
- **信号流向箭头**：金色箭头指示加密信号从右转子→中转子→左转子→反射器的路径

#### 控制按钮
| 按钮 | 功能 |
|------|------|
| **设置位置** | 手动将转子设置到指定字母位置（同时更新初始位置） |
| **🔄 重置** | 将转子恢复到配置时的初始状态 |
| **▶ 单步** | 手动触发一次转子步进（最右转子转动 1 步，观察双步进效果） |

## 操作流程示例

1. 启动程序：`python nngm.py`
2. 切换到「**机器配置**」标签页
3. 从预设下拉列表选择 `默认 (I-II-III, B, AAA-AAA)`，点击「加载并应用」
4. 如需手动调整配置，修改参数后点击「**Apply Configuration**」
5. 切换到「**加密 / 解密**」标签页
6. 在输入框输入 `HELLO WORLD`
7. 点击「**🔒 加密**」，观察输出结果
8. 将第 7 步得到的密文复制回输入框，点击「**Decrypt**」，验证输出还原为 `HELLO WORLD`

## 密码机原理简述

恩尼格玛机的信号路径：

```
键盘 → 插线板 → 右转子 → 中转子 → 左转子 → 反射器 → 左转子 → 中转子 → 右转子 → 插线板 → 灯板
```

- **插线板**：加密前后各经过一次，交换指定字母对
- **转子组**：信号正向通过 3 个转子（右→左），被反射器转向后，再反向通过（左→右）
- **转子步进**：每次按键最右转子前进 1 步（类似里程表）；当右转子到达缺口位置时，带动中转子也转一步；当中转子到达缺口位置时，中转子再次转动时会带动左转子（双步进机制）
- **反射器**：确保信号必定经过不同路径返回，实现加解密对称

### 双步进逻辑
真实恩尼格玛机的转子步进存在「双步进」现象：当中转子处于自身缺口位置时，下一次按键会同时转动中转子和左转子。本程序完整模拟了这一机制。

## 附录：程序更新（2026 年 5 月 25 日）

### 程序错误修复

本次更新修复了 `nngm.py` 中的以下程序错误：

#### 1. `EnigmaMachine._step_rotors()` 转子步进逻辑严重错误

**问题**：原实现在转子转动*之后*才检查缺口状态（`is_at_notch`），导致中转子/左转子的步进触发信号永远被错过。

```
原代码流程（错误）：
  转动右转子 → 检查上次步进信号 → 读取当前缺口状态作为下次信号
                                                ↑
                                          转子已离开缺口位置，信号丢失
```

**修复**：改为在转动*之前*采样各转子缺口状态，同一次按键中完成所有判定和转动。

```
修复后流程（正确）：
  读取缺口状态（转动前） → 右转子始终转动 → 右转子在缺口则转中转子 → 中转子在缺口则左/中转子同步转动
```

**影响**：修复前，中转子位于自身缺口时只带动左转子，自己没有同步再前进一步，导致双步进位置序列错误。

#### 2. GUI 转子显示顺序与内部模型不一致

**问题**：`EnigmaMachine` 内部按左转子 / 中转子 / 右转子保存转子，但配置页、手动位置控件和状态图按右转子 / 中转子 / 左转子标注时直接使用同一索引，导致“右转子”控件实际修改左转子。

**修复**：GUI 继续按右 → 左展示，读写配置时反转索引映射到内部左 → 右模型。默认预设内部仍为 `["I", "II", "III"]`，配置表中对应显示为 `["III", "II", "I"]`。

#### 3. 加载预设时状态不一致

**问题**：`_load_preset()` 直接通过 `Plugboard(preset["plugs"])` 更新了插线板，但转子、环设置、反射器等配置仅更新 UI 下拉框而未实际重建机器，导致 UI 显示与 `EnigmaMachine` 实例状态脱节。

**修复**：`_load_preset()` 改为调用 `_create_enigma_from_preset()` 完整重建密码机实例，确保 UI 与机器状态一致。按钮名称同步改为"加载并应用"以反映此行为。

#### 4. 废弃代码清理

移除了 `EnigmaMachine` 中的 `self.next_turn` 属性及相关逻辑（原用于延迟步进信号），步进信号现在直接在同一次调用中完成。
